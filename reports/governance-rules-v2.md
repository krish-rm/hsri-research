## Consolidated Standing Governance Rules (1–21)

### 1. Merge Authorization & Scope Gating
The agent may merge to `main` without per-merge human sign-off only when:
(a) the full pytest suite passes, with the summary pasted;  
(b) canonical Step 5 passes on production after deploy;  
(c) the merge is `--no-ff`, with no force-push or history rewriting;  
(d) every merge is reported with SHA and workflow run IDs.  

**Strict Human-Approved PR Restrictions:** A human-approved PR is **strictly required** for changes to:
- Governance rules
- The pass criteria or assertions of any verification script
- IRB, participant consent, debriefing, or risk assessment documents
- Public verdict labels

The human maintainer may revoke this merge authorization at any time.

### 2. No Imputation of Structural NaNs
Missing data arising from structural non-participation (e.g., non-EU status in EMLI, non-participating economies in PIAAC PSTRE) must be preserved as `NaN`. Under no circumstances may structural missingness be imputed, interpolated, or masked by synthetic mean substitution.

### 3. No Score Extrapolation to Unrated Nations
Composite and pillar scores must never be extrapolated or modeled for the 86 evaluated countries that lack qualifying multi-pillar indicator data. These nations remain strictly classified as unrated.

### 4. Mandatory Preview Disclaimer
All published interfaces, visualizations, tables, exports, preprint drafts, and repository distributions must prominently display the `v0.3-dev` preview disclaimer denoting the index as an exploratory research prototype.

### 5. Multi-Model Deliberative Log Provenance
Entries in `hsri_agents/divergence_log.csv` and associated queues must correspond to actual multi-model executions. Synthetic, hypothetical, or placeholder rows are strictly prohibited. Single-model executions must be explicitly labeled with their actual family; human entries must be labeled with `model_family: "human"`.

### 6. Behavioral Experiment Human Deployment Gate
Behavioral experiment batteries (EXP-01 through EXP-09) must **never** be deployed to human participants without prior institutional IRB-equivalent ethical review, informed consent, clinical safety debriefing, and designated Principal Investigator (PI) institutional oversight.

### 7. Verbatim Canonical Step 5 Gate Output
The canonical Step 5 verification script output (`ALL INDEPENDENT CHECKS PASSED`) must appear verbatim in the sprint execution report as a condition of release.

### 8. Production Verification Exclusivity
Local `dist/` or staging builds are strictly for developer debugging. Only live checks against the production deployment URL (`https://krish-rm.github.io/hsri-research/`) constitute valid PASS evidence.

### 9. Lane 4 Deliberative PRs are Draft Only
Pull requests generated by Lane 4 deliberative agent runs or proposed policy adjustments must remain in `draft` status pending explicit human maintainer review.

### 10. Conservative Default on Unresolved Questions
Unresolved methodological or empirical debates default to the most conservative posture (e.g., maintaining `NaN` policy, excluding contested imputations). Such rulings are logged as human entries and remain overridable by the maintainer.

### 11. Branch + PR Integration Workflow (Reconciled)
All development work must occur on isolated feature branches (`sprint-<N>/<task>`). The `main` branch receives changes **only** through a `--no-ff` merge of a feature branch that satisfies all conditions of Rule 1; direct commits to `main` are strictly prohibited. For any task that touches restricted files (governance rules, verification pass criteria, IRB documents, public verdict labels) or whenever uncertainty arises, the agent must open a draft PR and stop without merging.

### 12. Epistemic Verdict Language
Synthetic-persona pilots (LLM personas) test stimulus behavior only and provide zero empirical evidence regarding human cognition. The term "validated" is reserved strictly for human-participant empirical data. Stimulus batteries that pass synthetic constraint and discrimination gates must be labeled "stimuli cleared for IRB submission" or "stimuli cleared for IRB packaging", never "validated" or "PROCEED TO IRB".

### 13. Report Integrity & Single Timezone
Sprint execution reports must disclose all CI failures, retries, and workflow modifications undertaken to achieve a green build. All reported timestamps must be reconciled to a consistent single timezone convention (with local time clearly noted where specified).

### 14. Step 5 Gate Architecture Split
The canonical four-check Step 5 script (`scripts/step5_verify.py`) serves as the immutable, authoritative release gate. Supplementary checks (e.g., methodology page badge assertions in `scripts/step5_supplementary.py`) run as a separate diagnostic check, and their output must be reported in an independent section.

### 15. Credential Isolation & Tooling Boundaries
The agent must never read, extract, scrape, or reuse stored system credentials (e.g., via `git credential fill`, environment memory dumps, or OS keychain scrapers). The agent may utilize only explicitly provisioned tokens (e.g., GitHub CLI session or scoped environment secrets). If no token is provisioned, the agent must push the branch via standard git push and provide the maintainer with the compare URL to open the PR manually.

### 16. Verbatim Evidence Rule
Every reported PASS in a verification table must cite raw, unedited command output pasted verbatim (pytest summaries with test counts, full grep outputs, GitHub Actions run IDs with conclusions). Any claim lacking verbatim raw output must be classified and reported as `UNVERIFIED`.

### 17. Historical Record Immutability
Dated historical log entries, queue resolutions, divergence records, and prior sprint reports must never be retroactively rewritten in-place to conform to subsequent corrections. Historical discrepancies must be resolved by appending dated addenda or modifying only the specific inaccurate document with the correction explicitly noted.

### 18. No Authored Timestamps
Timestamps in reports, addenda, and logs must originate strictly from the system clock at the moment of writing (`Get-Date -Format o` / `date -Iseconds`) or from authoritative git commit metadata (`git log --format='%ad'`). Agents must never manually type, estimate, project, or backdate a timestamp. If an existing document contains an erroneous timestamp, it must be corrected via an addendum citing the real commit time.

### 19. Strict Stimulus Item Identity
Any report, analysis, table, or governance document that refers to a stimulus item must cite both its explicit `id` from the canonical JSONL file and the first 80 characters of its `stimulus_text`. Referring to stimuli solely by arbitrary item numbers (e.g., "Item 1") without unambiguous text and ID linkage is strictly prohibited.

### 20. No Invented Identifiers
Agents must never invent, hallucinate, or construct fictitious email addresses, ORCIDs, DOIs, usernames, personal contact details, or User-Agent contact strings (including in automated scripts querying public APIs). When contact metadata is required, agents must use a neutral identifier (`HSRI-Audit`) or a maintainer-supplied value.

### 21. Merge Permission by Task Type
Merge permissions are strictly governed by task type. For tasks classified as restricted (governance, verification scripts, IRB packages, public verdict labels), autonomous merges are forbidden and draft PRs are mandatory. When in doubt regarding task classification, the agent must open a draft PR and stop.

## What Changed in Version 2.0 and Why

1. **Reconciliation of Rules 1 and 11:**
   - *Issue in v1.0:* Rule 1 allowed merges under standing conditions, but Rule 11 stated "never push directly to main" without specifying the exact branch-to-main merge mechanism, creating ambiguity regarding whether an agent could execute `--no-ff` branch merges.
   - *Resolution in v2.0:* Rule 11 now explicitly states that all work occurs on feature branches (`sprint-<N>/<task>`) and that `main` is updated **only** via `--no-ff` branch merges under Rule 1 conditions. Direct commits to `main` are banned. If a task touches restricted categories, the agent opens a draft PR and stops.
2. **Addition of Rules 18–21 (Sprint 12 Additions):**
   - **Rule 18 (No Authored Timestamps):** Eliminates manual backdating and timezone guessing by mandating system-clock or git commit metadata provenance.
   - **Rule 19 (Item Identity):** Prevents mapping ambiguities between stimulus versions (such as the EXP-02 template vs. active stimulus confusion) by requiring canonical `id` and the first 80 characters of text.
   - **Rule 20 (No Invented Identifiers):** Prohibits invented email addresses (`@hsri.org`) in automated API scripts and metadata.
   - **Rule 21 (Merge Permission by Task Type):** Formalizes an explicit boundary matrix between tasks eligible for autonomous `--no-ff` merge and tasks requiring human PR review.
